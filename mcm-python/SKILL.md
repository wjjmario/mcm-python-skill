# 美赛建模 · Python

用中文讨论、英文撰写论文，尊重用户指定语言。交付可复现的计算、可追溯的论证和回应题目要求的论文；不承诺奖项，不编造数据、引用或运行结果。

## 启动与续做

判断用户需要备赛、选题、整题求解、局部修复、写作还是检查。已有项目先读题目、状态和产物，保留可靠工作；局部任务只读相应参考文件。

完整项目确认年份、题号、题目及附件、训练/正式参赛、剩余时间，能推断的不要重复询问。缺少题目时可搭环境或制定训练计划，不能编造题目要求。选题比较数据可得性、团队能力、可验证性和时间成本，不按 A–F 刻板分配算法。

正式比赛前读取 [规则与 AI 记录](references/contest-rules.md)，核验当届官方规则、题目附加要求和时间。无法核验时标明缺口，不声称合规。训练可按已核验快照练习。

新项目运行 `python <skill目录>/scripts/init_project.py <目标目录>`，不会覆盖已有目录。模板的合成演示不是赛题答案；实际建模替换示例并按需安装依赖。

备赛训练根据团队薄弱环节安排历史题或局部练习，明确目标、时间预算和验收依据，结束后依据实际产物复盘。正式项目按剩余时间制定可调整计划，优先完成全部要求的基线，预留写作、重算与 PDF 检查时间；临近停止修改期限时减少没有验证收益的新方法。

## 工作闭环

1. **拆题。** 将每个题面要求、输入、输出/单位、数据缺口、拟用模型和验证方法写入 `notes/problem-map.md`。区分题面事实、外部证据、假设和推导结论；保留原始数据，明确模拟数据。
2. **建模。** 读 [建模与验证](references/modeling.md)，先实现可解释基线，比较少量合理候选方法；只有验证支持才增加复杂度。交代变量、单位、假设、方程、参数来源及适用范围。
3. **求解。** 读 [Python 工程](references/python.md)，执行程序并保存配置、种子、环境和结果。验证方式匹配模型，做关键参数敏感性及必要的不确定性分析。未运行的代码标为未验证，不能报告貌似运行得到的指标。
4. **解释。** 每项答案关联实际结果文件、单位、情景和验证证据。记录失败、不利结果、不可识别参数及局限，不修改原始观测以迎合结论。
5. **写作。** 读 [论文写作](references/paper.md)，用已验证结果组织英文正文和图表，摘要最后写；按题目准备 memo/letter 等附加产物。最终编译/渲染 PDF 后检查格式、页数、匿名性、引用和 AI 披露。

## 状态与交付

完整项目维护 `notes/status.md`：阶段、已完成要求、关键决策、缺口、最近运行命令、下一步。维护 `notes/sources.csv` 的真实来源和 `notes/ai-use.jsonl` 的工具/模型、日期、用途、输入输出存档、团队核验；版本未知写未知，不伪造历史记录。

阶段交付包含产物路径、可信结论、验证证据、局限与下一步。整题交付包含英文论文源文件和可生成的 PDF、Python 代码、环境/运行方式、数据来源、结果图表、检查报告。代码和正文共用同一结果文件，修改模型后重算并同步摘要、表图和结论。

不自动创建新聊天或代理分工。正式比赛期间不向队外人员求助、不公开题目或团队工作。最终提交由团队操作，生成论文不等于已提交。
